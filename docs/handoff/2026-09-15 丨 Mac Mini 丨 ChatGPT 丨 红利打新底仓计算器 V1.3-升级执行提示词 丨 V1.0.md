# 1. 本轮产品目标

V1.3 要把现有工具从“指数估值 + 10万元底仓计算器”升级为一个完整的个人红利底仓管理工具。

完整流程应变成：

```text
看市场环境
→ 看红利指数估值与回撤
→ 选择指数
→ 首次建仓 / 追加投资 / 全面再平衡 / 清仓退出
→ 生成冻结的下单计划
→ 进入手机下单模式
→ 逐只复制股票代码到银河 APP
→ 确认已下单
→ 保存真实交易记录
→ 汇总当前真实持仓
→ 下一次继续追加或再平衡
```

核心原则：

> 计划与真实持仓分离。  
> “系统建议买多少”不是“已经持有多少”。  
> 只有用户明确确认“已下单 / 已卖出”的记录才能进入真实持仓账本。

# 4. 估值字段顺序

宽基和红利指数统一按以下字段顺序展示：

```text
指数名称 / 代码
→ 当前指数点位
→ 距近10年最高点回撤
→ 当前 PE
→ PE 历史分位
→ 当前 PB
→ PB 历史分位
→ 当前股息率
→ 股息率历史分位
→ 风险溢价
→ 风险溢价历史分位（有可靠数据时）
→ 综合估值解释
→ 官方核验
```

要求：

- 当前绝对值与历史分位不得混成一个字段；
- 显示数据日期；
- 显示数据来源；
- 显示 fetchedAt；
- 官方指数必须保留官方核验入口；
- 第三方分位不得冒充官方值；
- 不同口径不得直接覆盖。

估值规则沿用：

- PE / PB 历史分位越高 → 越贵；
- 股息率 / 风险溢价历史分位越高 → 越便宜。

颜色只是辅助，必须同时有文字判断。

# 5. 历史最高点回撤

正式统一使用“收盘对收盘”：

```text
drawdown = currentClose / highestClose - 1
```

禁止：

```text
当前收盘价 ÷ 历史盘中最高 high
```

近10年有完整历史的指数：

- 使用近10年最高“收盘点位”。

成立不足10年的指数：

- 使用成立以来最高“收盘点位”；
- UI 明确显示“成立以来回撤”；
- 不得显示成“10年回撤”。

至少显示：

- 当前收盘点位；
- 最高收盘点位；
- 最高点日期；
- 当前回撤百分比；
- 回撤标签。

推荐标签：

- 0% ～ -10%：高位附近
- -10% ～ -20%：轻度回撤
- -20% ～ -30%：明显回撤
- -30% ～ -40%：较深回撤
- < -40%：深度回撤

历史高点数据至少用两个独立来源做抽样核验；若无法双源核验，必须在 UI / 文档明确数据等级和限制。

例如：


```text

→ 价格与估值均出现一定安全垫。
```

解释必须直接来自展示数据，不允许引入不可见的黑箱评分。

# 11. 下单计划必须冻结

用户点击“进入手机下单模式”时，必须生成一个不可被后台行情偷偷修改的“计划快照”。

至少保存：

- batch_id；
- 投资周期；
- 投资类型；
- 指数；
- 指数权重快照版本 / 日期；
- 计划生成时间；
- 当时行情价格；
- 行情来源；
- 行情时间；
- 理论目标金额；
- 建议股数；
- 建议手数；
- 建议实际金额；
- 当时配置偏差。

进入执行阶段后：

- 当前价格可以继续刷新用于提示；
- 已冻结建议股数不得后台自动变化。

如果用户希望更新建议：

```text
重新计算剩余计划
```

必须显式确认。

如果已经有已确认订单：

- 不得改写已确认交易；
- 只能针对未处理 / 待复核部分重新计算；
- 重新计算必须生成可追溯的新 revision 或新计划版本。

# 13. 投资生命周期：四种模式

主入口增加：

1. 首次建仓
2. 追加投资
3. 全面再平衡
4. 清仓退出

---

## 13.1 首次建仓

适用于当前投资周期没有任何真实持仓。

用户输入：

```text
计划投入金额
```

系统按选定指数权重和交易规则计算建议买入。

完成手机下单并确认后，实际交易进入账本。

---

## 13.2 追加投资

这是长期使用的默认模式。

要求：

> 不是简单再把新增10万元按指数权重重新买一遍。

系统必须基于：

- 当前真实持仓股数；
- 当前最新价格；
- 当前最新指数权重；
- 当前策略剩余现金；
- 本次新增投入资金；

重新计算。

目标：

> 用新增资金优先补当前低配股票。

默认规则：

- 只买不卖；
- 已超配股票本轮可以为 0 股；
- 新增资金优先纠正低配；
- 整手 / 最小交易数量约束继续生效；
- 剩余无法配置现金继续记入策略现金余额；
- 不允许为了完美贴合权重自动卖出。

显示：

```text
当前持仓股数
当前持仓市值
当前实际权重
最新指数目标权重
追加后目标市值
当前低配金额
本轮建议增加股数
本轮建议实际投入
追加后预估权重
```

算法必须透明，可测试。

---

## 13.3 全面再平衡

高级模式。

系统允许生成：

- 买入建议；
- 卖出建议。

目标是把整个现有组合尽量重新贴近最新指数权重。

必须考虑：

- 当前真实持仓；
- 当前价格；
- 最新指数成分和权重；
- 交易单位；
- 可用现金；
- 交易方向。

默认只生成计划，不自动执行。

卖出同样通过手机专注模式逐只确认。

---

## 13.4 清仓退出

清仓不是删除数据。

点击“清仓退出”后：

1. 根据当前真实持仓生成全部卖出计划；
2. 进入“手机卖出模式”；
3. 逐只复制股票代码；
4. 用户在银河 APP 卖出；
5. 回网页确认“已卖出”；
6. 所有持仓归零后，允许结束当前投资周期。

当前周期标记：

```text
CLOSED / 已清仓
```

保留完整历史：

- 建仓；
- 追加；
- 再平衡；
- 清仓；
- 每笔确认交易；
- 每次计划；
- 每次实际持仓变化。

以后再做时：

```text
开始新的投资周期
```

生成新的 `cycle_id`，不得覆盖旧周期。

---

# 14. 指数调样对持仓的处理

指数调样后：

- 新成分股：进入最新目标权重；
- 被剔除股票：标记“非当前成分股”。

在“追加投资”只买不卖模式：

- 被剔除股票不自动卖；
- 明确列出“待处理非当前成分”；
- 是否卖出由用户决定。

在“全面再平衡”模式：

- 可以生成被剔除股票的卖出建议；
- 仍需用户逐笔确认。

开发代码：


正式部署副本：

```text
SQLITE_DB_PATH
```

# 20. 配置偏差

```text

```

公式：

```text

- 理论目标金额
```

解释：

```text
正数 = 买多
负数 = 买少
```

顶部至少显示：

- 理论目标总额；
- 建议实际投入；
- 总配置偏差；
- 未配置资金。

硬校验：

```text
所有行配置偏差之和
=
建议实际投入总额
-
理论目标总额
```

不一致即为计算 Bug，不得验收。
