# 红利打新底仓计算器 V1.3

[English](./README.en.md)

## 这是干什么的

把"红利指数估值判断 → 官方核对成分/权重 → 输入资金 → 计算每只股票应买金额、理论股数、合法买入股数/手数 → 冻结下单计划 → 手机辅助下单 → 人工确认成交 → 真实持仓与策略现金追溯"做成单人本地闭环工具，用于两市打新底仓管理。

只做计划、记录和核对，**不自动决定、不自动交易**，不接券商接口，不接 Supabase。目标运行环境是 Mac Mini 自托管、桌面浏览器操作。

## 快速开始（Mac）

双击：`启动工具.command`

浏览器会自动打开：`http://127.0.0.1:8765/`

关闭工具：回到终端窗口按 `Ctrl+C`。

命令行方式：

```bash
# 常规启动（默认端口 8765，自动打开浏览器）
python3 server.py

# 指定端口 / 不自动打开浏览器
python3 server.py --port 8765 --no-open

# 指定账本开发库路径（也可用环境变量 DIVIDEND_LEDGER_DB）
python3 server.py --db ./dev.db
```

> 不建议长期直接双击 `index.html`。直接 HTML 是降级模式，仍可读取包内/浏览器缓存，但无法稳定使用磁盘持久缓存、官方 XLS 同源代理和主备行情。

## 九个指数（三宽基＋六红利）

- 000300 沪深300
- 000905 中证500
- 000852 中证1000
- H30269 中证红利低波动指数
- 930740 沪深300红利低波动指数
- 930955 中证红利低波动100指数
- SPCLLHCP 标普中国A股大盘红利低波50
- 931468 中证红利质量指数
- 931446 中证东方红红利低波动指数

估值总览统一字段顺序：指数/代码 → 当前收盘 → 最高收盘与日期 → 回撤 → PE/PB/股息率及分位 → 联合解释 → 数据日期/来源/抓取时间 → 官方核验。页面每个指数旁保留相应的**官方指数页/事实表、官方编制方案、官方成分文件、官方权重文件（中证）**，用于人工复核。

## 回撤（近似口径，D9 上架）

回撤固定为 `当前收盘 / 同指数最高收盘 - 1`，且两个收盘必须来自**同一指数收盘序列**。

当前九指数尚无授权同口径十年历史序列，因此最高收盘采用近似口径：腾讯/东方财富近 10 年不复权收盘 `MAX(close)`，抓取失败的指数用参考站快照兜底并明确标注（含 `asOf`、来源与 crossChecks 交叉验证记录，见 `cache/valuation/drawdown.json` 与页面脚注来源行）。宽基为真实收盘序列近似，红利指数为快照/ETF 代理近似——均为诚实标注的近似值，不是官方双源核验值。

## 估值分位与风险溢价

- 估值分三层（课程 / 官方 / 第三方）各自标注口径与日期，不混口径、不合并分位。
- 宽基 PE/PB/股息率分位按证据门 B 例外引入公开估算（逐格标"估算"＋来源名＋日期＋URL），与课程层、官方层分区展示。
- 宽基风险溢价：无课程模板值，按参考站同款公式 `100 − PE分位` 反推显示并标"估算"（当前 36.2 / 22.3 / 30.2，对应 000300 / 000905 / 000852）；**股息率口径无授权同口径来源，仍显示"暂无数据"，不估算、不补造**。
- 无可靠来源的字段一律显示"暂无数据"，不编数，不用 ETF/个股/盘中 high 代理。

## 缓存怎么工作

三层保护：

1. **项目磁盘缓存（主）**：`cache/official/` 保存官方原始权重 XLS；`cache/parsed/` 保存解析后的成分 JSON；`cache/quotes.json` 保存最近一次成功行情。
2. **包内快照（兜底）**：当前已预置 930740 和 SPCLLHCP 的已核验快照。
3. **浏览器 localStorage（二级加速）**：不再是唯一缓存，因此清浏览器缓存不会删除 `cache/` 目录里的正式数据。

首次以正式方式联网启动时，网页会自动检查哪些中证指数缺少解析缓存，并尝试从中证官方补齐。以后官方站临时不可达时，旧缓存不会被清空。

桌面智能体更新官方原始权重缓存可先执行：

```bash
python3 server.py --prefetch-only --refresh
```

之后启动网站，让页面解析官方 XLS 并写入 `cache/parsed/`，再完成核对与验收。

## 行情源（三路＋五态）

顺序固定为：

**腾讯公开行情（主） → 东方财富公开行情（备用） → 本地最近成功行情缓存（兜底）**

每只股票行内显示"行情源 / 时间 / 数据日期 / 状态"。状态枚举五态：`LIVE` / `DEGRADED` / `CACHE` / `STALE_BLOCKED` / `MANUAL_OVERRIDE`。

契约：单次请求 `timeout=3s`；每源最多重试 2 次，退避 `0.5s → 1.5s`；10 分钟窗口内同一源连续 3 次失败标 `DEGRADED` 并切下一源；本地缓存最大陈旧 72 小时或跨 3 个交易日，超过标 `STALE_BLOCKED`（不伪装实时）；同一源连续 2 次全校验通过才恢复 `LIVE`。

两路公开接口仅供资金测算，不是券商委托行情；正式下单以券商盘口为准。普通价格在主表为**只读**。

### 手动覆盖区用法（高级异常处理，默认隐藏）

仅当三路行情都不可用且必须人工核价时，点"显示高级异常处理"展开默认隐藏的手动覆盖区。

手动覆盖只影响本页测算展示：写入本机 `localStorage`（键 `divManualOverride`），并标记 `MANUAL_OVERRIDE`；输入后回车生效，清空输入或点"清空全部手动覆盖"即恢复自动行情。

**手动覆盖价不进账本定价**：用带手动覆盖的股票新建冻结批次会被拒绝并提示。

## 投资周期与批次（账本闭环）

账本以 SQLite 保存 cycle（投资周期）、batch（下单批次）、order_item（逐只清单）、transaction（成交）、cash_ledger（策略现金）。

一个周期内可生成四类批次：`INITIAL` 首次建仓、`ADD` 追加投资（只买不卖、低配优先）、`REBALANCE` 全面再平衡（同时生成 BUY/SELL 计划）、`EXIT` 清仓退出（逐笔 SELL）。

批次可冻结为不可静默变化的计划快照（保存权重版本/日期、行情来源/时间、目标金额、建议股数、偏差、算法版本）；需要更新时显式生成新 `revision`，刷新行情不改已冻结的建议股数，已确认项不可改写。

**所有批次只生成计划，不自动执行、不自动下单、不自动卖出**；只有用户人工核实的成交才写入账本。测试批次可删除（含 CONFIRMED 需输入"确认删除"四字＋审计，CLOSED 拒绝）。

## 下单执行页（手机辅助）

进入「六、下单执行」，选择投资周期与批次，可切换 checklist 列表 / 单只专注模式。

每只股票四态处理：`PENDING` 待下单 / `CONFIRMED` 已确认成交 / `SKIPPED` 已跳过 / `REVIEW` 待复核；支持复制代码/名称/数量/单行记录，需要到银河 APP 人工下单。

**只有「已确认成交」会写入真实交易账本**（经 `record_transaction` 联动）；`CONFIRMED` 不能经状态接口直接设置，但可在行内输入"撤销确认"四字撤销（联动删除成交/现金事件，行回 PENDING，CLOSED 拒绝＋审计）。

完成门禁：全部处理为「已确认成交/已跳过」才通过（存在待下单或待复核即未通过）。刷新页面会从本地服务恢复进度。

## 持仓与历史页（只读）

「七、持仓与历史」为只读页；持仓**默认从 confirmed 成交重建**（视图 `v_holdings`），显示数量、均价、成本、成分状态与来源声明。

同时显示策略现金余额与现金事件流水（追加式事件账本，可追溯）。

非当前成分持仓以 `STALE_CONSTITUENT` 标记保留显示，不向其分配新 BUY，清仓时照常全仓卖出。

## 账本开发库与隔离

- 账本默认使用开发库 `./dev.db`；数据库路径可用 `--db <path>` 或环境变量 `DIVIDEND_LEDGER_DB` 覆盖。
- **开发库与容器库隔离**：开发/测试只允许使用临时或开发库 `./dev.db`，不得触碰生产目录；Docker 方式的账本固定在容器内 `/data/ledger.db`（`DIVIDEND_LEDGER_DB`），与本地开发库互不相通，见下节。
- `.db` / `.db-wal` / `.db-shm` / `var/` / `DockerData/` / `DockerBackups/` 已被 `.gitignore` 排除，数据库运行文件不进 Git；静态服务拒绝暴露 `db/` 目录与 `.db` 文件，浏览器只能走 API 访问账本。
- 演示数据均为虚构且可清除；备份/恢复请使用 SQLite `.backup` 或 `VACUUM INTO`，恢复后校验 `integrity_check` 与 `foreign_key_check`。
- 全量回归：`python3 scripts/ledger_smoke_test.py`（在系统临时目录建开发库，全程不触碰正式库/生产目录），当前 **282/282 EXIT=0**。

## Docker 部署（可选，单机常驻）

仓库自带 `Dockerfile`、`compose.yaml`、`.dockerignore`、`docker/env.template` 四件套，构建后容器内服务监听 8000，宿主端口默认 8771（实测返回 200）。

1. 先在宿主机准备两个**已存在**的目录（数据目录、备份目录；Compose 不会静默创建）。
2. 复制模板并填写真实值（私密值只放 `.env.local`，不进 Git）：

```bash
cp docker/env.template docker/.env.local
# 填 PROJECT_SLUG / COMPOSE_PROJECT_NAME / APP_PORT / PUBLIC_APP_URL
#     APP_DATA_DIR / APP_BACKUP_DIR / IMAGE_TAG
```

3. 构建并启动（四件套为 D11 交付，容器健康检查 30s 一次）：

```bash
docker compose --env-file docker/.env.local up -d
```

4. 浏览器访问 `http://127.0.0.1:<APP_PORT>/`（默认 `8771`）。

容器内账本固定写 `/data/ledger.db`、行情缓存固定写 `/data/quotes.json`，均在数据目录内，与本地 `./dev.db` 完全隔离；备份目录以只读方式挂进 `/backups`。
